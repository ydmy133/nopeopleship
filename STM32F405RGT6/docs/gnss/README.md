# GNSS 采集模块（v6 严格轮询接收）

## 本次修正

- 当前 USART2 / PA2-TX / PA3-RX / 9600 / 8N1、设备地址0x50。用户已将GPS设置为9600，板端同步匹配。
- 只发送读请求 `50 03 00 49 00 08 98 5B`，正常响应必须完整21字节。
- 删除缺帧头重建、帧头损坏容错、字节流扫描、请求回显过滤/接受路径。
- 删除自动解锁、写MODDELAY、SAVE和失败后的自动配置。固件不改变传感器设置，也不撤销先前固件可能已经写入的设置。
- 与磁力计对照：USART2 NVIC及RXNE/PE/ERR中断关闭，主循环独占SR/DR。HAL发送等待TC后立即读取SR/DR，不在发送后清空或等待。轮询逐字节保留错误；完整响应等IDLE结束后解析，短帧累计到100ms总窗口。
- 禁止ISR或HAL接收同时读取USART2 DR。停止接收后才解析并更新数据。
- 任何PE/NE/FE/ORE/缓存溢出均拒绝整次事务，即使CRC正确也不更新数据。
- 完整合法零坐标响应为状态7（未定位）；通信错误保留旧样本但返回失败。
- 保留完整原始接收缓存，包括CRC，最多64字节，不补字节、不清洗。

## MQTT诊断

`gnss_diag.v=6`；字段为 `last/rx/err/hex/exception`。删除了旧版 `delay/delay_step/delay_us`。上层业务字段和既有状态编号保持；新增UART错误状态11。

|字段|含义|
|---|---|
|last|0成功；1发送失败；2无响应；3长度不符；4帧头不符；5CRC错误；7通信成功但零坐标；10合法Modbus异常；11UART错误|
|rx|实际累计接收长度；正常21字节，不接受回显和额外字节|
|err|位掩码：1奇偶、2噪声、4帧错误、8硬件溢出、16缓存满|
|hex|完整原始捕获（最多128个十六进制字符），正常42字符且以500310开头|
|exception|完整且CRC正确的0x83异常码；每次查询前清零|

UART错误优先于长度错误。例如13字节同时FE时，v6返回11、rx=13、err=4；不要误认为丢字节问题变成了另一种问题。

## 验证结果和范围

真实驱动主机回归覆盖：正确请求、首字节在TX返回时已就绪、分段到达、缺头/13字节短帧、错误地址/功能码/字节数、CRC失败、回显前缀、CRC正确但UART错误、溢出、无响应、发送超时、Modbus异常、失败不更新数据、无自动写配置、JSON缓冲边界。

`tests/gnss_receive/fixtures/wit_gps_register_snapshots.bin` 来自用户维特记录中的550帧CRC正确87字节响应。提取0x49..0x50寄存器，生成等价21字节单元测试响应；这是测试夹具，生产固件不做重建。550组均能得到零坐标/零地速并正确解码GPSYAW。CSV记录频率不代表GNSS定位更新频率。

Keil工程：`MDK-ARM/STM32F405RGT6.uvprojx`；输出：`MDK-ARM/STM32F405RGT6/STM32F405RGT6.hex`；本次构建日志：`MDK-ARM/gnss_polling_build.log`。

测试和构建验证代码，不能证明板卡115200通信已经恢复。上电验证目标为v=6、rx=21、err=0、完整CRC正确响应；室内无定位时gnss_status=7是合理结果。

## 根因调查

见 `RS485_TURNAROUND_ASSESSMENT.md`。硬件收发时序问题仍待测量；这次修改修正了软件接受坏帧的问题，不承诺修复被硬件遮挡的字节。不能用补帧、放宽CRC或单纯换成DMA替代换向波形检查。

## 磁力计与GPS对照结论

|项目|磁力计|v5 GPS|v6 GPS对照版本|
|---|---|---|---|
|接收方式|HAL ReceiveToIdle阻塞轮询|自定义RXNE中断|主循环直接轮询SR/DR|
|NVIC|USART3关闭|USART2开启|USART2关闭|
|完整响应长度|23|21|21|
|缺头处理|会补50 03再验CRC|拒绝|拒绝|
|逐字节FE/NE检查|该HAL轮询路径未检查|检查|检查|
|更新数据|解析成功时|捕获结束且严格验证后|捕获结束且严格验证后|

磁力计成功不能直接证明23字节完整无UART错误。v6对照只改变GPS接收方式及帧结束判断，保留严格检查，不复制磁力计补头逻辑，不改变GPS配置，不修改正常磁力计驱动。

用户15:09:03.367至15:09:05.235串口工具记录有18组同请求/完整响应，显示时间差9..13ms；最新响应CRC=5E48（线上5E 48），GPSYAW寄存器0x243C=92.76度，经纬度/地速为0。实际驱动回归已验证此帧应返回7并更新yaw；串口工具时间戳不能直接当作线上的设备回复延迟。

v6已构建通过（0错误0警告）；尚未由用户烧录并实测。若v6恢复完整21字节、err=0，则接收方式/中断路径成为重点；若仍为13字节+FE，则该路径差异不能解释问题，继续做同板卡同接口的控制变量测试及波形检查。
