# 无人船上位机：安装包封装与版本升级方案

本文说明如何把当前 Qt Quick 上位机（`usv_gcs`）做成用户可安装的软件，以及如何做「设置页显示当前/最新版本 → 点击升级」的联网更新。

当前工程状态：

- 桌面端 Windows x64 Qt 应用，产物是 `usv_gcs.exe` + Qt 运行库目录
- 配置写在用户注册表 `HKEY_CURRENT_USER\Software\Zhudian\UsvGcs`
- 预置位库与日志在 `%APPDATA%\Zhudian\UsvGcs`
- 现场目前是「整目录拷贝」，见 [部署说明.md](部署说明.md)
- **还没有** 安装向导（`.exe` 安装包）、Android（`.apk`）、版本检查与在线升级

建议分两期：

| 期次 | 目标 | 说明 |
|------|------|------|
| 一期（推荐先做） | Windows 安装包 + 设置页在线升级 | 现场上位机都是 Windows，投入小、立刻能用 |
| 二期 | Android APK + 应用内升级 | 需要 Qt for Android 工具链、重新适配触控/权限/屏幕，工作量明显更大 |

不要把现有的 `usv_gcs.exe` 改个后缀当 APK。Windows 可执行文件和 Android 安装包是两套构建产物。

---

## 1. 总体架构

```text
开发机编译 Release
        │
        ├─ Windows：windeployqt 收集运行库
        │         → Inno Setup 打成 UsvGcs-1.2.0-setup.exe
        │         → 用户运行安装包，自己选安装路径
        │
        └─ Android（二期）：Qt Android Kit 编译
                  → 签名 APK / AAB
                  → 用户侧装或走应用市场

发布时同时上传：
  1) 安装包文件（setup.exe 或 apk）
  2) latest.json（版本清单，给软件联网查询）

用户打开设置页：
  显示当前版本 1.0.0
  请求 latest.json → 发现 1.2.0
  点击「版本升级」→ 下载安装包 → 校验哈希 → 退出程序并拉起安装程序
```

版本号建议统一用 **语义化版本** `主.次.修订`（与 `CMakeLists.txt` 里 `project(usv_gcs VERSION 1.0.0)` 对齐），例如：

- `1.0.0` 首次交付
- `1.0.1` 修 bug，协议不变
- `1.1.0` 新功能（设置页升级、新通信选项等）
- `2.0.0` 不兼容变更（协议大改、配置格式变更）

另外再维护一个单调递增的整数 **versionCode**（如 `100`、`101`、`110`），用来比较「谁更新」，避免字符串比较出错。

## 2. Windows：封装成可自定义路径的安装包（.exe）

目标：用户拿到一个 `UsvGcs-x.y.z-setup.exe`，双击后出现安装向导，**可以改安装目录**，装完桌面有快捷方式，开始菜单能卸载。

推荐工具：**Inno Setup 6**（免费、中文友好、工业软件常用）。备选：NSIS、WiX、Qt Installer Framework。

### 2.1 安装包里必须带什么

只拷 `usv_gcs.exe` 会无法启动。安装目录应包含 `windeployqt` 之后的整棵树：

```text
{用户选择的安装目录}\
  usv_gcs.exe
  Qt6Core.dll / Qt6Gui.dll / Qt6Quick.dll / ...
  platforms\qwindows.dll
  sqldrivers\qsqlite.dll
  imageformats\
  tls\                    （Qt6 走系统 Schannel，一般已有）
  QtQuick\  QtQml\  ...   （QML 插件）
  opengl32sw.dll          （无独显时软件渲染）
  vc_redist.x64.exe       （可选：安装时静默装 VC++ 运行库）
```

QML 源码已打进 `resources.qrc`，**不必**把工程里的 `qml\` 源文件装进安装目录。

配置和预置位 **不要** 放进安装目录。现在已经写在用户 AppData / 注册表，换安装路径、升级覆盖程序文件时，船号、Broker、返航点都还在。

### 2.2 开发机打包流水线

在工程根目录（含 `CMakeLists.txt`）执行：

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH=D:\Qt\6.8.3\msvc2022_64
cmake --build build --config Release

D:\Qt\6.8.3\msvc2022_64\bin\windeployqt.exe --release --qmldir qml build\bin\Release\usv_gcs.exe
```

确认 `build\bin\Release` 能在一台 **没有装 Qt** 的电脑上双击启动后，再拿这个目录去打安装包。

建议把上述步骤写成 `scripts\package-windows.bat`，避免每次手工操作漏插件。

### 2.3 Inno Setup 脚本要点（用户可选路径）

安装 [Inno Setup 6](https://jrsoftware.org/isinfo.php)，新建 `installer\usv_gcs.iss`，核心写法如下。

```iss
#define MyAppName "无人船控制系统"
#define MyAppVersion "1.0.0"
#define MyAppPublisher "Zhudian"
#define MyAppExeName "usv_gcs.exe"

[Setup]
AppId={{8F3A2C1E-7B4D-4E9A-9C11-USVGCS000001}
AppName={#MyAppName}
AppVersion={#MyAppVersion}
AppPublisher={#MyAppPublisher}
; 默认路径，用户可在向导里改
DefaultDirName={autopf}\Zhudian\UsvGcs
DefaultGroupName={#MyAppName}
OutputDir=..\dist
OutputBaseFilename=UsvGcs-{#MyAppVersion}-setup
Compression=lzma2
SolidCompression=yes
WizardStyle=modern
ArchitecturesAllowed=x64compatible
ArchitecturesInstallIn64BitMode=x64compatible
; 允许用户浏览/修改安装路径（不要写成 yes）
DisableDirPage=no
PrivilegesRequired=admin
UninstallDisplayIcon={app}\{#MyAppExeName}
SetupLogging=yes

[Languages]
Name: "chinesesimplified"; MessagesFile: "compiler:Languages\ChineseSimplified.isl"

[Tasks]
Name: "desktopicon"; Description: "创建桌面快捷方式"; GroupDescription: "附加任务"

[Files]
; 把 windeployqt 后的整个 Release 目录打进去
Source: "..\build\bin\Release\*"; DestDir: "{app}"; Flags: ignoreversion recursesubdirs createallsubdirs
; VC++ 运行库（从微软下载 vc_redist.x64.exe 放到 installer\redist\）
Source: "redist\vc_redist.x64.exe"; DestDir: "{tmp}"; Flags: deleteafterinstall

[Icons]
Name: "{group}\{#MyAppName}"; Filename: "{app}\{#MyAppExeName}"
Name: "{group}\卸载 {#MyAppName}"; Filename: "{uninstallexe}"
Name: "{autodesktop}\{#MyAppName}"; Filename: "{app}\{#MyAppExeName}"; Tasks: desktopicon

[Run]
; 静默安装 VC++ 2015-2022 x64 运行库（已装则跳过）
Filename: "{tmp}\vc_redist.x64.exe"; Parameters: "/install /quiet /norestart"; StatusMsg: "正在安装运行库..."; Flags: waituntilterminated
Filename: "{app}\{#MyAppExeName}"; Description: "立即运行 {#MyAppName}"; Flags: nowait postinstall skipifsilent

[UninstallDelete]
; 不要删除 AppData 里的配置和预置位库
```

向导行为：

1. 欢迎页 → 许可（可选）→ **选择安装目录**（默认 `C:\Program Files\Zhudian\UsvGcs`，用户可改成 `D:\USV\gcs` 等）
2. 是否创建桌面图标
3. 复制文件、装 VC++ 运行库
4. 可勾选「立即运行」

升级安装时 Inno Setup 用同一个 `AppId` 识别旧版本：用户再跑新的 `setup.exe`，会覆盖 `{app}` 里的程序文件，**不会清注册表和 `%APPDATA%\Zhudian\UsvGcs`**。

卸载：控制面板 / 设置 → 应用 → 卸载。预置位默认保留（现场换机时还能拷走）；若产品要求「卸载连数据一起删」，再单独加卸载页勾选项，默认不要勾。

### 2.4 安装路径相关注意

| 项 | 建议 |
|----|------|
| 默认目录 | `{autopf}\Zhudian\UsvGcs`（64 位系统即 `C:\Program Files\Zhudian\UsvGcs`） |
| 用户改路径 | 保持 `DisableDirPage=no`，不要禁用目录页 |
| 程序写文件 | 安装目录可能对普通用户只读（装在 Program Files 时）。日志、配置、SQLite **必须继续写 AppData**，不要改回安装目录 |
| 单实例锁 | 现有 `%TEMP%\usv-qt-gcs.lock` 可保留；升级前安装程序应先结束 `usv_gcs.exe` |
| 防火墙 | 安装脚本里可用 `[Code]` 调 `netsh advfirewall`，也可继续按《部署说明》手工放行 |

升级前结束进程，可在 `.iss` 的 `[Code]` 里加：

```pascal
function InitializeSetup(): Boolean;
var
  ResultCode: Integer;
begin
  Exec('taskkill', '/F /IM usv_gcs.exe', '', SW_HIDE, ewWaitUntilTerminated, ResultCode);
  Result := True;
end;
```

现场操作时程序可能正在控船，**应用内升级必须先弹确认**，不要静默强杀。安装包被运维手动运行时，强杀可以接受。

### 2.5 代码签名（强烈建议）

未签名的安装包在 Win10/11 上常被 SmartScreen 拦截，用户会看到「未知发布者」。

1. 购买或申请 Windows 代码签名证书（OV / EV）
2. 用 `signtool sign` 签 `usv_gcs.exe` 和 `UsvGcs-*-setup.exe`
3. 时间戳服务器一并写上，证书过期后旧包仍显示有效

没有证书时，至少把安装包放到你们自己的 HTTPS 站点，并告知用户：「发布者显示未知时选仍要运行」。不要依赖邮件随意转发的 exe。

### 2.6 和「绿色版目录拷贝」的关系

安装包是给最终用户的。开发/应急仍可继续拷 `Release` 整目录。两种发布物建议同时保留：

- `UsvGcs-1.2.0-setup.exe` — 正式安装、可改路径、可卸载、可走在线升级
- `UsvGcs-1.2.0-win64.zip` — 绿色包，给不能跑安装向导的现场

## 3. Android：封装成 .apk（二期）

当前工程是 `WIN32` 桌面可执行文件，**不能直接产出 APK**。要做平板/手机端，需要单独的 Android 构建。

### 3.1 要先想清楚的产品问题

上位机 HUD 按 **1920×1080 桌面全屏** 设计，有键鼠快捷键（WASD、Ctrl+Alt+Q）。APK 上至少要处理：

- 竖屏/横屏、异形屏、DPI
- 触控替代十字舵与快捷键
- 后台保活与锁屏（控船时不能被系统杀掉）
- 定位、网络、前台服务权限
- MQTT/UDP 在移动网络下的稳定性
- 地图瓦片地址 `http://210.76.81.182` 是明文 HTTP，Android 9+ 默认禁止明文，要开 `usesCleartextTraffic` 或改 HTTPS

若现场其实是工控机 / Windows 加固平板，**不必做 APK**，把 Windows 安装包做好即可。

### 3.2 工具链

- Qt 6.8（与桌面同一大版本更省事）的 **Android** 组件
- Android Studio / SDK / NDK / JDK 17
- CMake 已支持 Android；需要补：

  - `android/AndroidManifest.xml`
  - `android/build.gradle`
  - 应用图标、启动页
  - `QT_ANDROID_PACKAGE_SOURCE_DIR`

CMake 里桌面用 `add_executable(usv_gcs WIN32 ...)`，Android 应改为按平台分支，例如：

```cmake
if(ANDROID)
    qt_add_executable(usv_gcs ${USV_SOURCES} ${USV_HEADERS} resources.qrc)
    set_target_properties(usv_gcs PROPERTIES
        QT_ANDROID_PACKAGE_SOURCE_DIR "${CMAKE_CURRENT_SOURCE_DIR}/android"
        QT_ANDROID_VERSION_NAME "${PROJECT_VERSION}"
        QT_ANDROID_VERSION_CODE 100
    )
else()
    add_executable(usv_gcs WIN32 ${USV_SOURCES} ${USV_HEADERS} resources.qrc)
endif()
```

Qt Creator 选 Android Kit → Build APK。命令行大致是：

```bat
cmake -S . -B build-android -DCMAKE_TOOLCHAIN_FILE=<NDK>/build/cmake/android.toolchain.cmake -DANDROID_ABI=arm64-v8a -DCMAKE_PREFIX_PATH=<Qt>/android_arm64_v8a
cmake --build build-android --config Release
```

产物一般在 `build-android/android-build/build/outputs/apk/`。

### 3.3 签名与安装

- **调试包**：Qt 默认 debug 签名，只能给开发机 `adb install`
- **发布包**：用自己的 keystore 签名（`apksigner` / Android Studio）

```text
keytool -genkey -v -keystore usv_gcs.jks -alias usvgcs -keyalg RSA -keysize 2048 -validity 10000
```

keystore 和密码只放构建机/密钥柜，**不要进 Git**。

用户安装：

- 拷到平板，文件管理器打开 APK（需允许「未知来源」）
- 或 `adb install -r UsvGcs-1.0.0.apk`
- 上架华为/应用宝等则还要对应市场的签名与隐私合规

Android App Bundle（`.aab`）只给 Google Play；国内分发通常仍用 **APK**。

### 3.4 版本号

`AndroidManifest` / Gradle：

- `versionName`：给用户看的 `"1.2.0"`（与 Windows 一致）
- `versionCode`：整数，每次上架必须比上次大

应用内升级比 Windows 更受系统限制，见第 5.3 节。

## 4. 版本发布通道（两个平台共用）

无论 exe 还是 apk，在线升级都依赖一个 **固定 URL 的版本清单** + **安装包下载地址**。

### 4.1 建议的目录结构

用你们已有的 HTTPS 站点、对象存储（OSS/COS）或内网文件服务器均可。示例：

```text
https://update.zhudian.example/usv_gcs/
  latest.json
  latest-android.json
  packages/
    UsvGcs-1.0.0-setup.exe
    UsvGcs-1.0.0-win64.zip
    UsvGcs-1.0.0.apk
    UsvGcs-1.1.0-setup.exe
    ...
  changelog/
    1.1.0.md
```

内网现场若上不了公网，把同一套文件放到船端能访问的局域网 Nginx 即可。设置页可留「更新服务器地址」，默认写成你们的正式 URL。

### 4.2 `latest.json` 约定

```json
{
  "appId": "usv_gcs",
  "platform": "windows-x64",
  "version": "1.2.0",
  "versionCode": 120,
  "minVersionCode": 100,
  "mandatory": false,
  "publishedAt": "2026-09-11T10:00:00+08:00",
  "changelog": "1. 设置页支持检查更新\n2. 修复 MQTT 重连偶发失败",
  "package": {
    "fileName": "UsvGcs-1.2.0-setup.exe",
    "url": "https://update.zhudian.example/usv_gcs/packages/UsvGcs-1.2.0-setup.exe",
    "size": 52428800,
    "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
  }
}
```

字段说明：

| 字段 | 作用 |
|------|------|
| `version` | 显示给用户的版本号 |
| `versionCode` | 整数比较；本地 `>=` 该值则「已是最新」 |
| `minVersionCode` | 低于此值强制升级（协议不兼容时用） |
| `mandatory` | `true` 时设置页只留「立即升级」，不给跳过 |
| `url` | 安装包直链，必须 HTTPS |
| `sha256` | 下载后校验，防止截包篡改 |
| `changelog` | 设置页展示的更新说明 |

Android 用 `latest-android.json`，`platform` 为 `android-arm64`，`url` 指向 apk。

**比较规则**：只比 `versionCode`，不要用字符串比 `"1.10.0"` 和 `"1.9.0"`。

### 4.3 每次发版清单（发布人员）

1. 改版本号：`CMakeLists.txt` 的 `VERSION`、`main.cpp` 的 `setApplicationVersion`、Inno Setup 的 `#define MyAppVersion`、Android 的 `versionName` / `versionCode`（最好只在 CMake 一处定义，其余生成）
2. 编译 Release，`windeployqt`，打 `setup.exe`，计算 SHA256
3. 上传安装包
4. 更新 `latest.json`（先传包，再改 json，避免用户查到新版本却 404）
5. 内部先装旧版，走一遍「设置 → 升级」验收
6. 通知现场：版本号、是否强制、是否需要停航操作

SHA256 示例（PowerShell）：

```powershell
Get-FileHash .\dist\UsvGcs-1.2.0-setup.exe -Algorithm SHA256
```

### 4.4 版本号建议只维护一处

在 `CMakeLists.txt`：

```cmake
project(usv_gcs VERSION 1.2.0 LANGUAGES CXX)
# 发布计数，每次发版 +1
set(USV_VERSION_CODE 120)
```

编译时生成头文件：

```cpp
// 生成的 src/app/Version.h（构建时写入 build 目录）
#define USV_VERSION_STR "1.2.0"
#define USV_VERSION_CODE 120
```

`main.cpp`：

```cpp
app.setApplicationVersion(QStringLiteral(USV_VERSION_STR));
```

Inno Setup 可用命令行 `/DMyAppVersion=1.2.0` 注入，避免三处手改漏改。

## 5. 应用内升级：设置页「当前版本 / 最新版本 / 点击升级」

### 5.1 用户看到的交互（Windows）

设置页增加一块「关于 / 版本」：

```text
当前版本    1.0.0
最新版本    检查中…  /  1.2.0  /  已是最新  /  网络不可用
更新说明    （有新版本时展开 changelog）

[检查更新]     [版本升级]
```

推荐流程：

1. **进入设置页时自动检查一次**（需能访问更新服务器；超时 5–8 秒，失败只提示「无法获取最新版本」，不影响控船）
2. 当前版本来自 `Qt.application.version`（即 `setApplicationVersion`）
3. 有新版本：最新版本号用高亮，「版本升级」可点
4. 已是最新：「版本升级」禁用或变成「已是最新」
5. 点击「版本升级」：
   - 若正在手动/巡航控船，先确认「升级将退出程序，请确认船端已停控或处于安全状态」
   - 下载到 `%TEMP%\Zhudian\UsvGcs\update\`，显示进度
   - 算 SHA256，与 json 不一致则删除并报错，不要运行
   - 成功后启动新 `setup.exe`，参数建议：

     ```text
     /VERYSILENT /NORESTART /SUPPRESSMSGBOXES /DIR="当前安装目录"
     ```

     `/DIR` 保证升级装回用户当初选的路径，而不是又跑到默认 Program Files
   - 本进程 `QCoreApplication::quit()`，让安装程序覆盖 exe
6. 安装结束可加 `/LAUNCH` 或 Inno 的 `postinstall` 自动拉起新版本
7. 新版本启动后再请求一次 `latest.json`，确认 `versionCode` 已对齐

强制升级（`mandatory` 或本地 `< minVersionCode`）：进入设置（或启动后）提示必须升级；HUD 是否锁操作由产品决定，控船软件建议 **不要在航行中强制退出**，只在设置页/空闲时拦截。

### 5.2 Windows 实现要点（Qt）

新增模块即可，不必改通信协议。建议文件：

```text
src/update/UpdateChecker.h
src/update/UpdateChecker.cpp
```

职责：

- `Q_PROPERTY`：`currentVersion`、`latestVersion`、`status`（idle/checking/available/upToDate/error/downloading）、`progress`、`changelog`、`errorString`
- `Q_INVOKABLE void checkForUpdates()`
- `Q_INVOKABLE void startUpgrade()`
- 内部用 `QNetworkAccessManager` GET `latest.json`，再 GET 安装包
- 用 `QCryptographicHash::Sha256` 校验
- 用 `QProcess::startDetached(setupPath, args)` 拉起安装包

当前安装目录：

```cpp
const QString installDir = QCoreApplication::applicationDirPath();
```

把它传给 Inno 的 `/DIR=`。注意路径含空格时要加引号。

设置页 QML 绑定示例：

```qml
Text { text: t("当前版本", "Current") + ": " + Qt.application.version }
Text { text: t("最新版本", "Latest") + ": " + usv.updater.latestVersion }

DarkButton {
    text: t("检查更新", "Check update")
    onClicked: usv.updater.checkForUpdates()
}
DarkButton {
    text: t("版本升级", "Upgrade")
    enabled: usv.updater.status === "available"
    onClicked: usv.updater.startUpgrade()
}
```

`UsvBridge` 里暴露 `updater`，与现有 `usv.settings` 同一套上下文。

网络失败不要重试轰炸；用户点「检查更新」再查。定时后台检查若要做，间隔建议 ≥ 6 小时，且仅在空闲时。

### 5.3 Android 应用内升级

Android 8+ 安装新 APK 需要权限 `REQUEST_INSTALL_PACKAGES`，并用 `FileProvider` 把下载的 apk 交给系统安装器。流程：

1. 读 `latest-android.json`
2. 下载 apk 到应用私有目录
3. 校验 SHA256
4. `Intent.ACTION_VIEW` / `ACTION_INSTALL_PACKAGE` 唤起系统安装界面
5. 用户确认后安装（系统会结束旧进程）

注意：

- 国内厂商 ROM 对「未知来源」限制不同，要引导用户打开
- 应用市场分发时，**不要自己下 APK**，应跳转市场详情页
- 企业内部分发（不上架）才走「下载 APK + 唤起安装器」

Qt 侧可用 `QDesktopServices` / 少量 JNI。工作量比 Windows 大，建议 Windows 闭环后再做。

### 5.4 为什么不直接覆盖正在运行的 exe

Windows 上正在运行的 `usv_gcs.exe` 无法被自己删掉或完整覆盖。标准做法是：

- **整包安装程序升级**（本文推荐）：下载 setup.exe → 退出 → Inno 覆盖 `{app}`
- 或做独立 `updater.exe`：主程序退出后由 updater 解压 zip 再拉起主程序

第一种和「用户手动跑安装包」是同一条路，运维也熟悉，优先用它。

不要用「只替换一个 exe、dll 还是旧的」的热补丁，Qt 插件版本不一致会直接打不开。

## 6. 安全与现场约束

| 风险 | 做法 |
|------|------|
| 假更新服务器 | 清单和安装包必须 HTTPS；有条件再给 json 做签名（公钥编进程序） |
| 安装包被篡改 | 必须校验 `sha256`；校验失败禁止执行 |
| 航行中退出 | 升级前确认；强制升级也等到停控/锚泊 |
| 升级失败变砖 | Inno 覆盖失败可再跑上一版 `setup.exe`；绿色 zip 留一份在 U 盘 |
| 配置丢失 | 升级只动 `{app}`，不动 `%APPDATA%\Zhudian\UsvGcs` 和注册表 |
| 密码进仓库 | 更新服务器若需鉴权，用只读 token；Broker 密码继续只放本机 |
| HTTP 地图 | 与升级通道分开；升级通道不要走明文 HTTP |

单实例：升级拉起安装包前要释放 `%TEMP%\usv-qt-gcs.lock`，否则新进程会立刻退出。`quit()` 后析构里删锁即可；安装程序里的 `taskkill` 作为保底。

## 7. 推荐落地顺序

### 第一步：能打出带路径选择的安装包（不改业务代码）

1. 固定 `windeployqt` 脚本
2. 写 `installer\usv_gcs.iss`
3. 产出 `UsvGcs-1.0.0-setup.exe`
4. 在一台干净 Windows 上：自定义装到 `D:\test\gcs`，确认能启动、能连 MQTT、卸载后程序文件消失、AppData 配置仍在

### 第二步：版本号与设置页展示

1. CMake / `main.cpp` 统一 `1.0.0`
2. 设置页增加「当前版本」显示（即使暂时不能在线检查，现场也方便对版本）

### 第三步：更新服务器 + 检查更新

1. 上传 `latest.json`（可先把 `version` 写成与当前相同，验证「已是最新」）
2. 实现 `UpdateChecker::checkForUpdates()`
3. 再发 `1.0.1`，验证设置页能显示最新版本号

### 第四步：一键升级

1. 下载、进度、哈希、拉起 Inno 静默安装、退出
2. 用 `/DIR=当前安装目录` 保证还装回用户选过的路径
3. 失败回滚说明写进设置页和《部署说明》

### 第五步（可选）：Android

1. 评估是否真的需要平板 APK
2. 加 Android 工程文件、签名、明文 HTTP 策略
3. 再做 `latest-android.json` 与安装器跳转

## 10. 一句话结论

- **Windows**：`windeployqt` 整目录 → **Inno Setup** 打成 setup.exe → 向导里 `DisableDirPage=no` 让用户选路径；配置继续放 AppData。
- **发版**：安装包放到 HTTPS，再更新 `latest.json`（含 `versionCode`、下载 URL、SHA256）。
- **升级**：设置页读 json，比较 `versionCode`，用户点击后下载 setup.exe，校验哈希，用 `/DIR=当前安装目录` 静默安装并退出本进程。
- **APK**：必须用 Qt Android 另编一包，不能从现有 exe 转换；应用内更新走「下载 APK + 系统安装器」，工作量单独排期。
