# 无人船上位机（usv_gcs）部署说明

本文说明如何把本项目部署到现场 **Windows 上位机**，并完成与船端的 MQTT / UDP 联调。  
程序为独立 Qt Quick 桌面应用（可执行文件名 `usv_gcs.exe`，窗口标题「无人船控制系统」），**不需要**安装 Java、Node、Electron 或 Spring Boot。

---

## 1. 部署前需要知道的几件事

| 项目 | 说明 |
|------|------|
| 程序 | `usv_gcs.exe`（CMake 工程名 `usv_gcs`，版本 1.0.0） |
| 目标系统 | Windows 10 / 11 **64 位** |
| 推荐分辨率 | **1920×1080**（设计稿）；其它分辨率会按 16:9 等比缩放并留边，默认无边框全屏 |
| 编译器 | 当前仓库以 **MSVC 2022 x64** 构建 |
| Qt | 官方 **Qt 6.5+** 或 **Qt 5.15**；模块：Core / Gui / Quick / Qml / Network / Sql / Svg（Qt5 另需 QuickControls2） |
| MQTT | 内置 MQTT 3.1.1 客户端，**不需要** Qt MQTT 组件 |
| 单实例 | 同时只能运行一份；重复启动会立刻退出 |

当前开发机构建使用官方 **Qt 6.8.3 MSVC 2022 64 位**（`D:\Qt\6.8.3\msvc2022_64`），产物为 `Qt6*.dll`。不要和 Anaconda Qt（`Qt5*_conda.dll`）混放在同一目录。

## 2. 上位机环境要求

### 2.1 硬件与系统

- CPU：x64，双核及以上
- 内存：建议 8 GB 及以上
- 显卡：支持 OpenGL / Direct3D（无独显时走软件渲染 `opengl32sw.dll`，已包含在打包目录中）
- 显示器：推荐 1920×1080；其它常见分辨率可全屏等比缩放；触控屏可用，键鼠同样可用
- 中文字体：系统需有 **微软雅黑**（中文版 Windows 默认已有；纯英文系统请先安装中文语言包）

### 2.2 必须安装的运行库

MSVC 编译的程序依赖 **Visual C++ 2015–2022 x64 可再发行组件**：

- 下载：https://learn.microsoft.com/zh-cn/cpp/windows/latest-supported-vc-redist  
- 安装文件：`vc_redist.x64.exe`  
- 未安装时，双击 `usv_gcs.exe` 会提示缺少 `VCRUNTIME140.dll` / `MSVCP140.dll`

无需在上位机安装 Qt、CMake 或 Visual Studio（采用「整目录拷贝」时）。

### 2.3 网络

按现场通信方式准备：

| 模式 | 上位机需要 |
|------|------------|
| MQTT（默认） | 能访问 Broker 的 TCP 端口（默认 **1883**；TLS 常见 **8883**） |
| UDP | 本机网卡能绑定接收端口（默认 **10193**），并能向船端 **10123** 发报文 |
| HUD 地图 | 能访问重点船舶服务系统 **http://210.76.81.182** 的 `kinth-map` 瓦片（天地图/卫星图，免登录）。不能访问时 HUD 底图为空白，其它操控不受影响 |

这些瓦片 **不需要** 高德/百度 API，也 **不需要** `/msaPlatform` 登录 token。`/msaPlatform`、`/hwService`（AIS、船舶位置等）要 token 续期，当前版本未调用。

关闭或放行 Windows 防火墙，见第 4.3 节。

## 3. 方式 A：拷贝已打包目录（现场首选）

开发机上若已经完成 `windeployqt`，产物在：

```text
<工程目录>\build\bin\Release\
```

该目录内应同时有：

- `usv_gcs.exe`
- Qt 运行库（官方构建为 `Qt5*.dll` / `Qt6*.dll`；Anaconda 构建为 `Qt5*_conda.dll`）
- `platforms\qwindows.dll`（缺了会报 *This application failed to start because no Qt platform plugin could be initialized*）
- `sqldrivers\qsqlite.dll`（预置位 SQLite 库）
- `imageformats\`（含 `qpng.dll`、`qsvg.dll`）
- QML 运行时目录：`QtQuick\`、`QtQuick.2\`、`QtQml\` 等

### 3.1 拷到上位机

1. 将整个 `Release` 文件夹复制到上位机，建议路径：

   ```text
   C:\Zhudian\usv_gcs\
   ```

2. 不要只拷 `usv_gcs.exe`。QML 界面资源已打进 exe（`resources.qrc`），但 **Qt 插件和 QML 模块必须和 exe 放在同一棵目录树里**。
3. 在桌面建立快捷方式，目标指向 `C:\Zhudian\usv_gcs\usv_gcs.exe`。
4. 首次运行前安装第 2.2 节的 VC++ 运行库。
5. 双击启动。约 1.4 秒启动画面后进入全屏 HUD。

退出：`Ctrl+Alt+Q`。全屏/窗口：`F11` 或 `Esc`。

## 4. 方式 B：从源码编译并打包（开发机）

在开发机完成，再把打包目录拷到上位机。

### 4.1 准备工具链

1. 安装 **Visual Studio 2022**（勾选「使用 C++ 的桌面开发」）
2. 安装 **CMake 3.16+**（VS 2022 自带即可）
3. 安装 **Qt 5.15 或 Qt 6.5+**（MSVC 64-bit），组件至少包括：

   - Qt Quick / Qt Quick Controls 2 / Qt QML
   - Qt Network
   - Qt SQL（SQLite）
   - Qt SVG

记下 Qt 根目录，当前开发机为：

```text
D:\Qt\6.8.3\msvc2022_64
```

### 4.2 编译 Release

在工程根目录（含 `CMakeLists.txt` 的目录）打开「x64 Native Tools Command Prompt for VS 2022」，或普通终端中先进入 VS 开发环境。配置时不要把 Anaconda 的 `Library\bin` 放在 PATH 前面，以免误找到 conda Qt。

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH=D:\Qt\6.8.3\msvc2022_64
cmake --build build --config Release
```

编译成功后可执行文件：

```text
build\bin\Release\usv_gcs.exe
```

### 4.3 用 windeployqt 收集运行库

必须在 **编译所用的同一套 Qt** 上执行。把 `windeployqt` 所在的 `bin` 加入 PATH，或写绝对路径。

```bat
cd build\bin\Release
windeployqt --release --qmldir ..\..\..\qml usv_gcs.exe
```

`--qmldir` 指向工程里的 `qml` 目录，用于收集 Quick Controls 2、Layouts、Window 等 QML 插件。界面源码本身已编进 exe，上位机 **不必** 再拷 `qml\` 源文件。

Qt 6 在 Windows 上走系统 Schannel（打包目录里的 `tls\qschannelbackend.dll`），普通 TLS 一般不必再拷 OpenSSL。若仍使用 Qt 5 构建，TLS 才需要对应的 `libssl` / `libcrypto`。

普通 TCP 1883（TLS 关闭）不需要额外 SSL dll。部署目录中应有 `qt.conf`，把插件路径指到 exe 旁边的 `platforms`、`qml` 等文件夹。

打包完成后，将整个 `build\bin\Release` 目录按第 3 节拷到上位机。

## 5. 防火墙与网卡

以管理员 PowerShell 执行（按实际端口修改）：

**MQTT 出站（连远程 Broker）：**

```powershell
New-NetFirewallRule -DisplayName "USV GCS MQTT Out" -Direction Outbound -Protocol TCP -RemotePort 1883 -Action Allow
```

TLS 时把 `1883` 改成 `8883`。

**UDP 收遥测 / 发控制（默认端口）：**

```powershell
New-NetFirewallRule -DisplayName "USV GCS UDP In"  -Direction Inbound  -Protocol UDP -LocalPort 10193 -Action Allow
New-NetFirewallRule -DisplayName "USV GCS UDP Out" -Direction Outbound -Protocol UDP -RemotePort 10123 -Action Allow
```

UDP 模式下：

- 「UDP 本机地址」应填 **上位机自己的网卡 IP**（默认示例 `192.168.1.81`）
- 「UDP 船端地址」填船端 IP（默认示例 `192.168.1.80`）
- 若本机 IP 与填写值不一致，程序会回退绑定 `0.0.0.0:10193`，日志中会出现 `UDP bind fallback to 0.0.0.0:10193`

现场建议把上位机与船端（或 4G 路由器）设为固定 IP，避免 DHCP 变化后对不上。

## 6. 首次启动与联调

HUD 右下角齿轮进入设置页。改完通信参数后必须点 **「应用通信设置并重连」**，否则链路不会切换。

「地图图层」可在 **天地图**（默认）与 **卫星图** 之间切换，底图来自重点船舶服务系统 `kinth-map`，不走高德/百度。地图服务地址默认 `http://210.76.81.182`。

### 6.1 MQTT（默认）

出厂默认值：

| 项 | 默认 |
|----|------|
| 通信模式 | `mqtt` |
| Host | `127.0.0.1` |
| Port | `1883` |
| TLS | 关 |
| 用户名 | `java_backend` |
| 密码 | 空（须在设置页填写，**不要写入仓库**） |
| Boat ID | `usv_001` |
| 遥测订阅 | `usv/+/telemetry/#` |
| Client ID | 首次启动自动生成 `usv-qt-gcs-xxxxxxxx` |

主题约定：

- 下行控制：`usv/{BoatID}/cmd/control`
- 上行遥测：订阅 `usv/+/telemetry/#`（例如 `usv/usv_001/telemetry/state`）

注意：

1. Client ID 不要与其它客户端（含旧 Java 后端）重复，否则 Broker 会互踢。
2. 账号权限需能 **发布** 控制主题、**订阅** 遥测主题。
3. 断线后约 **15 秒** 自动重连。
4. 自签证书可打开「忽略证书」；生产环境应使用正规证书并关闭该项。

连接成功时状态类似：`MQTT usv_001 @ 10.0.0.8`；失败为 `MQTT 未连接`。详细过程见日志（第 7 节）。

### 6.2 UDP

将通信模式改为 `udp`，填写本机/船端地址与端口，再点「应用通信设置并重连」。

UDP 报文为 **UTF-8 JSON payload**（无额外帧头），与协议文档中的控制/遥测 JSON 一致。

绑定成功时状态类似：`UDP 192.168.1.81:10193`。

### 6.3 现场建议先做的业务设置

在设置页一并完成：

1. **一键返航地址**：有有效定位后点「获取当前 GPS 并保存」
2. **自动返航地址**：同上
3. **断连保护 / 低电量保护**：默认开启，按规程决定是否关闭
4. 语言、主题、显示单位按操作员习惯设置

低电保护误触发且需紧急机动时，可点「强制退出低电保护」（会下发 `move_speed=20`）。仅用于应急。

## 7. 配置、数据库与日志位置

程序启动时在 **exe 同级** 创建 `data` 文件夹，配置、预置位库和日志都写在这里，调试时直接打开程序目录即可。

开发机上常见路径：

```text
<工程目录>\build\bin\Release\data\
```

现场绿色版常见路径：

```text
C:\Zhudian\usv_gcs\data\
```

| 内容 | 文件 |
|------|------|
| 通信与界面配置 | `data\usv_gcs.ini` |
| 预置位 / 返航点库 | `data\usvdb.sqlite` |
| 运行日志 | `data\usv_gcs.log` |
| 单实例锁 | `%TEMP%\usv-qt-gcs.lock` |

设置页底部也会显示「数据目录」和「运行日志」的完整路径。

首次从旧版本升级时，会把注册表里的配置和 `%APPDATA%\Zhudian\UsvGcs\usvdb.sqlite` 自动拷到 `data\`（目标文件已存在则不覆盖）。

若 exe 所在目录对当前用户只读（例如装在 `C:\Program Files`），会改写 `%APPDATA%\Zhudian\UsvGcs`，并在日志里给出警告。现场建议装到可写目录（如 `C:\Zhudian\usv_gcs`）。

备份：拷贝整个 `data` 文件夹即可恢复船号、Broker、预置位和返航点。

## 9. 升级与回滚

1. 退出程序（`Ctrl+Alt+Q`）。若提示另一实例在运行，结束任务管理器中的 `usv_gcs.exe`，或删除过期的 `%TEMP%\usv-qt-gcs.lock`。
2. 将新的 `Release` 整目录覆盖到 `C:\Zhudian\usv_gcs\`（先把旧目录改名为 `usv_gcs.bak` 以便回滚）。
3. **不要删除** 新目录里的 `data\`，也不要用空的 `data` 覆盖已有配置，否则预置位和 ini 会丢失。
4. 启动后确认版本行为与链路状态。异常则把备份目录改回。

Qt 大版本更换（5 ↔ 6）或从 Anaconda Qt 换成官方 Qt 时，必须 **整目录替换**，不能只换 exe。

## 11. 故障排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 提示缺少 `VCRUNTIME140.dll` | 未装 VC++ 运行库 | 安装 `vc_redist.x64.exe`（x64） |
| *no Qt platform plugin* | 缺少 `platforms\qwindows.dll` 或 Qt dll 不匹配 | 用同一套 Qt 重新 `windeployqt`，整目录部署 |
| 窗口空白 / QML 报错 | 缺少 `QtQuick`、`QtQuick.2` 等目录 | `windeployqt --qmldir qml` 后重拷 |
| 闪一下就退出 | 已有实例，或 QML 加载失败 | 查任务管理器；看 `data\usv_gcs.log` |
| `MQTT 未连接` | 地址/端口/账号错误，或防火墙拦截 | ping / telnet Broker 端口；核对主题权限；看日志 `MQTT connecting` / `MQTT:` |
| MQTT 连上又掉 | Client ID 冲突 | 在设置里改成唯一 ID |
| TLS 失败 | 缺 OpenSSL dll 或证书不被信任 | 拷贝匹配的 libssl/libcrypto；或临时打开「忽略证书」验证 |
| `UDP bind failed` | 端口被占用或无权限 | 换端口；检查是否有其它程序占用 10193 |
| 预置位无法保存 | 缺少 `sqldrivers\qsqlite.dll` 或 `data` 目录不可写 | 补齐插件；确认 exe 目录可写（不要装在 Program Files） |
| 中文方框 | 没有微软雅黑 | 安装中文语言包 |
| 界面四周有黑边 | 屏幕比例不是 16:9 | 正常现象（按 1920×1080 等比缩放）；F11 可退出全屏 |

日志同时写到 stderr 和 `data\usv_gcs.log`。现场排障请先看该文件末尾。

## 12. 安全注意

- Broker 密码只存在本机 `data\usv_gcs.ini` 中，**不要**写进 `CMakeLists.txt`、脚本或 Git。
- 公网 MQTT 应使用 TLS，并限制账号只能访问对应 `usv/{船号}/#`。
- 上位机建议独立账号、关闭不必要的共享；程序目录需对操作员可写（至少 `data` 文件夹），以便保存配置、预置位和日志。
- 本程序可直接下发推进/舵令，部署后须按操作规程使用，避免误触手动十字舵。
